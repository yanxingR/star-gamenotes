# v2 · 年度评选（2025 / 2026）+ 玩家投票

这是一个独立的工作副本，原有 `site/`、根 `index.html`、`old.html`、工作流等都没有改动。

- 首页：`/v2/`（首屏最高分位置已换成奖项轮播）
- 投票：`/v2/vote.html`（2026 星GN 玩家投票，当前领先和实时结果都在这页）

## 年度结构

- **2025**：官方获奖名单已确定，首页 2025 tab 显示这 6 个奖；tab 标签显示「站内评选」，评选范围为站内已评分作品。
- **2026**：投票进行中，没有预设获奖者。首页 2026 tab 显示每个奖项当前票数最高的游戏；票数为 0 的奖项显示「还没有人投票」；投票页和选择器都标注「站内已收录的 2026 游戏」。投票截止 **2026-12-31 23:59（北京时间）**，玩家投票结果作为 2026 星GN 正式评选的参考，正式评选会结合结果调整。
- 首页默认打开 2026；切到 2025 看官方名单。

## 2026 星GN 玩家投票

- 6 个奖项，**每个奖项可投可不投**，只投玩过的即可，至少选 1 项就能提交。
- **对站内已收录的 2026 游戏开放**：每个奖项点「选择游戏」打开选择器，里面是当前收录的 2026 年游戏，支持按名称、类型、厂商搜索；不再限制在 5 个提名里。
- 截止时间：**2026-12-31 23:59（北京时间）**；截止后选择器、提交按钮和修改功能全部关闭，结果继续展示。
- 同一浏览器每个奖项一票；**提交后可以随时回来修改**，改完重新提交即覆盖旧票。
- 每个奖项卡片会显示当前领先游戏和票数；页面底部实时显示完整结果。
- 首页 2026 轮播按各奖项当前票数取第一名，票数写在卡片上；截止后首页标签变为「投票已结束」，入口改为「查看投票结果」。
- 投票服务失败时，状态旁显示「重试」按钮，点击会重新连接并重新加载结果。

## 奖项数据

`awards.js` 里包含：

- `categories`：6 个奖项，`name` 是展示名（星系列），`desc` 是「星GN 年度…」副标题
- `editions`：2026（票数届，`winners` 为空）、2025（官方名单）

`build_awards.py` 可以从 `../data.json` 重新生成：

```bash
python v2/build_awards.py
```

2026 年结束后，如果要把 2026 也变成官方名单：在 `build_awards.py` 的 `EDITIONS` 里给 2026 填上 `winners`，再加 2027 的投票届，并把 `currentVoteYear` 改成 2027；重新生成后，首页会自动多出年份 tab。

## 投票后端

在 Supabase SQL Editor 执行一次 `supabase-votes.sql`：

- `votes` 表不再允许前端直接插入，所有写入统一走 `submit_votes` 函数
- `vote_totals` 视图只暴露聚合票数
- `submit_votes` 函数用于「修改投票」：检查截止时间、频率限制后，删除该浏览器本年度的旧票，再写入新票
- 每个浏览器每个奖项一票（`voter_id + year + category` 唯一）
- 只提交选了的奖项，所以支持部分投票
- 截止时间：每年 12-31 23:59:59（Asia/Shanghai），服务端也会拒绝超时提交
- 基础防刷：同一 IP 哈希 10 分钟内最多 12 次提交；`vote_submit_log` 只保存 IP 哈希，不保存原始 IP

如果之前已经建过 `votes` / `vote_totals`，这次需要**重新执行一次更新后的 `supabase-votes.sql`**：它会建截止/频率控制逻辑、撤销前端直接 insert，并重建 `submit_votes` 函数。

没有执行 SQL 时，投票页会显示「投票服务未配置」，但奖项轮播不受影响。

如果提交时报 `Could not find the table 'public.votes' in the schema cache`：

1. 在 SQL Editor 重新执行 `supabase-votes.sql`；
2. 如果 `votes` 表已经存在、还是这个报错，再执行一次 `notify pgrst, 'reload schema';`，等几秒刷新；
3. 用 `select to_regclass('public.votes') as votes_table, to_regclass('public.vote_totals') as totals_view;` 检查两个对象是否都存在。

## 部署

把整个 `v2` 文件夹上传到仓库根目录，Pages 会提供 `/v2/`。要让 `v2` 成为正式首页，把根目录跳转页里的 `site/` 改成 `v2/` 即可（这一步需要修改当前只读的根 `index.html`）。

## 数据更新

`v2/data.js` 是静态兜底；投票页连上 Supabase 后会再用实时 `games` 表刷新 2026 游戏列表。数据库新增 2026 游戏时，投票选择器会自动包含它们；首页轮播也读实时 `games`，不需要重新生成 `awards.js`。
