## 2026 星GN 玩家投票

- 7 个奖项：年度星光之冠、年度动人星语、年度星尘奇迹、年度星界旅人、年度极速流星、年度绮丽星云（最佳美术）、年度声光星海（最佳视听体验）；**每个奖项可投可不投**，只投玩过的即可，至少选 1 项就能提交。
- **类型范围**：最佳独立/角色扮演/动作只列出符合条件的 2026 游戏；最佳美术/最佳视听对所有游戏开放。
- **对站内已收录的 2026 游戏开放**：每个奖项点「选择游戏」打开选择器，支持按名称、类型、厂商搜索；不再限制在 5 个提名里。
- 截止时间：**2026-12-31 23:59（北京时间）**；截止后选择器、提交按钮和修改功能全部关闭，结果继续展示。
- 同一浏览器每个奖项一票；**提交后可以随时回来修改**，改完重新提交即覆盖旧票。
- 每个奖项卡片会显示当前领先游戏和票数；页面底部实时显示完整结果。
- 首页 2026 轮播按各奖项当前票数取第一名，票数写在卡片上；截止后首页标签变为「投票已结束」，入口改为「查看投票结果」。
- 投票服务失败时，状态旁显示「重试」按钮，点击会重新连接并重新加载结果。
- 拆分前投过「最佳艺术游戏」的旧票会复制到「最佳美术」和「最佳视听体验」两边的计数里；之后修改投票时两项分别选择。

## 独立游戏口径

没有统一的法定定义，本站按「开发独立性 + 发行/资金结构 + 规模」判断，不按玩法类型判断。

- **严格独立**：独立团队，自发行或独立厂牌发行，非大厂主导，规模非 3A。全库 25 部，2026 有 8 部。
- **广义独立**：独立工作室，但由中型/大厂发行或 AA 规模；全库再加 10 部，共 35 部，2026 共 13 部。是否算作独立奖取决于站主口径。
- 当前投票使用**严格名单**；候选表见 `v2/indie-candidates.csv`，含 id、名称、年份、严格/广义、开发商。
- Supabase 的 `games.genre` 也要追加「独立」：执行 `v2/add-indie-tag.sql`，会给严格名单 25 部追加 `/独立`，可重复执行。
- 前端判断独立奖时同时接受「genre 含独立」和静态 `indieIds`，所以数据库标签更新后即使 `awards.js` 未重新生成，也能识别；新增独立游戏只要在 Supabase 打上「独立」标签即可。
- 标签更新后，等 Actions 同步 `v2/data.js` 即可；`v2/data.js` 现在由 `build_data.py` 直接生成，不再复制其他站的静态文件。
- `name_en` 已进 `build_data.py` 和搜索逻辑；执行 `v2/add-name-en.sql` 后，等 Actions 同步即可搜索英文名。
- 33号远征队（Sandfall/Kepler）、MIO（Douze Dixièmes/Focus）、明末（505）等属于广义候选；丝之歌、小丑牌、动物井、米娜等在严格名单内。

## 奖项数据

`awards.js` 里包含：

- `categories`：7 个奖项，`name` 是展示名（星系列），`desc` 是「星GN 年度…」副标题
- `editions`：2026（票数届，`winners` 为空）、2025（官方名单，7 个奖）
- `indieIds`：严格独立名单（25 部），投票最佳独立奖只从这里取
- `indieBroadIds`：严格 + 广义候选（35 部），留给以后切换宽口径

`build_awards.py` 可以从 `../data.json` 重新生成：

```bash
python v2/build_awards.py
```

2026 年结束后，如果要把 2026 也变成官方名单：在 `build_awards.py` 的 `EDITIONS` 里给 2026 填上 `winners`，再加 2027 的投票届，并把 `currentVoteYear` 改成 2027；重新生成后，首页会自动多出年份 tab。

## 投票后端

在 Supabase SQL Editor 执行一次 `supabase-votes.sql`：

- `votes` 表不再允许前端直接插入，所有写入统一走 `submit_votes` 函数
- `vote_totals` 视图只暴露聚合票数
- `submit_votes` 函数用于「修改投票」：检查截止时间、频率限制后，删除该浏览器本年度的旧票，再写入新票
- 每个浏览器每个奖项一票（`voter_id + year + category` 唯一）
- 只提交选了的奖项，所以支持部分投票
- 截止时间：每年 12-31 23:59:59（Asia/Shanghai），服务端也会拒绝超时提交
- 基础防刷：同一 IP 哈希 10 分钟内最多 12 次提交；`vote_submit_log` 只保存 IP 哈希，不保存原始 IP
- 单次最多 7 个奖项（拆分后从 6 改为 7）
- 已有的 `art` 票会复制一份到 `av`，让拆分前的艺术票同时计入最佳美术和最佳视听体验

这次拆分奖项后，必须**重新执行一次 `supabase-votes.sql`**：除了截止/防刷逻辑，还要把 `submit_votes` 的奖项上限改成 7，并执行 art→av 迁移。

没有执行 SQL 时，投票页会显示「投票服务未配置」，但奖项轮播不受影响。

如果提交时报 `Could not find the table 'public.votes' in the schema cache`：

1. 在 SQL Editor 重新执行 `supabase-votes.sql`；
2. 如果 `votes` 表已经存在、还是这个报错，再执行一次 `notify pgrst, 'reload schema';`，等几秒刷新；
3. 用 `select to_regclass('public.votes') as votes_table, to_regclass('public.vote_totals') as totals_view;` 检查两个对象是否都存在。

## 部署

把整个 `v2` 文件夹上传到仓库根目录，Pages 会提供 `/v2/`。根目录的 `index.html` 已改为跳转 `v2/`，上传根 `index.html` 后根网址会进入新版；v2 仍保留 `/v2/` 路径。

## 数据更新

`v2/data.js` 是静态兜底；投票页连上 Supabase 后会再用实时 `games` 表刷新 2026 游戏列表。数据库新增 2026 游戏时，投票选择器会自动包含它们；首页轮播也读实时 `games`，不需要重新生成 `awards.js`。

但独立奖使用静态 `indieIds` 名单：新增独立游戏后，要更新 `build_awards.py` 里的 `INDIE_STRICT`，重新生成 `awards.js`，否则新游戏不会进入最佳独立奖的选择器。
